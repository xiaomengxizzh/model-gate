D2 并发写探测：同一 state 目录的双写者（2026-11-11）
====================================================

背景：目录生成器文档里写着"单写者假设"，但没有证据。本探测把两个生成进程同时指向同一个 `--state-dir`，
观察 5 轮后的输出与状态文件是否损坏。

复现：node scripts/test/codex-catalog-race.mjs（可用 MG_RACE_ROUNDS 调轮数）

结果：4/4（5 轮）
```text
rounds=5 bothExit0=5 outputCorrupt=0 stateJsonCorrupt=0
PASS  两个并发进程均成功（5/5）
PASS  输出文件未损坏
PASS  状态目录 JSON 未损坏
PASS  --status 在并发后仍可用
```

## 如何解读（重要）

- 这**不能证明没有竞争**：5 轮未复现损坏，只说明当前实现（版本文件名带版本号+sha、写入经临时文件）
  把冲突面压得比较小，且最坏情况是"后写者覆盖指针"（last-writer-wins），而不是文件损坏。
- 真正的多写者语义仍未被定义：两个进程可能各自认为自己是 current；`--list-versions` 可能出现两个同编号版本。
- 因此文档与 UI 仍应保持"单写者"约束；若要支持多写者，需要显式锁与版本合并策略（当前不做）。

## 边界

- 仅测并发生成，不测与 `--rollback` 的并发；不测跨主机/网络文件系统。
- 未做故障注入（写一半杀进程）；原子 rename 保证的是"不会读到半截文件"，不是"多写者一致"。
