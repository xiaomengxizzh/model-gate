## 3. R008-3：跨授权域 429（**FAIL**，产品阻断）

配置（全回环）：模型 `cross-child` 的 provider 是 `rate-api`（api-key 域，回环 mock 固定回 429 速率限流），`fallbacks: ['sub-domain']` 指向**另一个授权域**：

- `sub-domain` = `codex-subscription`（`gatewaySubscription.enabled=true`，官方 host 语义）；
- `sub-domain-app` = `siwc-app`（第二个对照域，无官方 key 门，用于观测"是否真的被发送"）。

实际结果（`receipts-r008-3-dual-domain.json`）：

| 对照 | 期望 | 实测 | 另一域命中增量 |
| --- | --- | --- | --- |
| 429 → `codex-subscription` 域 | 429 `cross_domain_fallback_blocked`，另一域 0 命中 | **403 `official_credential_missing`**（换域已被执行，仅因缺网关 key 停下） | 0（未真正发出，但授权域已切换） |
| 429 → `siwc-app` 域 | 429 `cross_domain_fallback_blocked`，另一域 0 命中 | **200，响应来自另一域 mock**（`OTHER-DOMAIN`） | **+1（实际跨域发送）** |

网关日志（脱敏片段，来自 `/api/logs`）：

```text
[info]  send authz generation=config-declared (unscoped) provider=rate-api domain=thirdParty
[warn]  upstream retryable status 429 attempt 1 / 1 attribution=rate_limit
[info]  send authz generation=config-declared (unscoped) provider=sub-domain domain=official
[warn]  responses 目标发送授权被拒绝 official_credential_missing sub-domain
[info]  send authz generation=config-declared (unscoped) provider=rate-api domain=thirdParty
[warn]  upstream retryable status 429 attempt 1 / 1 attribution=rate_limit
[info]  send authz generation=config-declared (unscoped) provider=sub-domain-app domain=thirdParty
```

### 根因（单一、可定位）

1. `src/forward.js:945` 对 `429` 使用 `typedSendError('MG_FB_RATE_LIMITED', …)` **抛出**，而不是返回 `{ok:false,status:429}`。
2. `src/index.js` 的跨域阻断点 `crossDomainFallbackBlocked`（`index.js:671`，调用点 `index.js:1249`、`index.js:1867`）判断条件都是 `up.status === 429`，因此**不可达**。
3. 抛出的错误落到各候选循环的 `catch`（`index.js:1263 / 1373 / 1782 / 1882 / 2264`）→ `lastErr = err; continue` → 换下一个候选，**跨授权域回退发生**。

即：策略检查写在了"返回值路径"上，而 429 只走"异常路径"。这也解释了为什么此前没有任何离线用例覆盖 `cross_domain_fallback_blocked`：该分支在真实调用链上没有入口。

### 最小改法（建议由 Lead 在 `src/index.js` 合入；本任务禁改 `src/**`）

在 5 处候选循环的 `catch` 中，把"429 异常"按同一策略拦截（以 `proxyNativeResponses` 为例）：

```js
} catch (err) {
  if (err && err.aborted) throw err
  // A4/V2-REAL-5：429 由 forward() 以 typedSendError 抛出，必须在换候选前按授权域收敛。
  if (err && err.code === 'MG_FB_RATE_LIMITED' && crossDomainFallbackBlocked(state, candidates, pid, prov)) {
    agg(state, pid, 'errors', 1); state.st.counters.errors += 1
    markFail(state, pid, prov.circuit)
    return { status: 429, contentType: 'application/json; charset=utf-8', buf: Buffer.from(JSON.stringify({
      error: { code: 'cross_domain_fallback_blocked', type: 'auth_domain_failure', kind: 'rate_limited',
               authDomain: providerAuthDomain(prov), status: 429, terminal: true, fallbackAllowed: false,
               message: '上游限流且存在跨授权域候选：按真实授权域返回，不换供应商/不换套餐' } })) }
  }
  lastErr = err
  …
}
```

同一段判断需要出现在媒体/embedding/rerank 等 `catch`（`index.js:1263 / 1373 / 2264`）与 Responses 原生路径（`index.js:1882`）。
更彻底的做法（二选一，由 Lead 决定）：在 `src/forward.js` 中对 `retry:false` 场景不再抛 429，而是返回 `{ok:false,status:429,retryAfter}`，让既有"返回值路径"统一生效——影响面更大，需重跑 chat/media 全套回归。

**回归建议**：把本脚本的 R008-3 两条对照纳入门禁（零真实上游，纯回环），并新增 `scripts/test/offline/` 单测直接调用 `decide`/`catch` 分支断言 `cross_domain_fallback_blocked`。

## 5. R009：双身份隔离

### 5.1 安装/实例级隔离（PASS_REAL）

两个实例：A（18882，client key/admin token A）、B（18883，client key/admin token B），各自独立 `MG_CONFIG_DIR`（`/tmp`）+ 独立 `HOME`，配置含各自的租户标记 `MARKER-TENANT-A-…` / `MARKER-TENANT-B-…`。

用 **A 的凭据** 访问 **B**（读/写/刷新三类动作，全部应 401/404）：

| # | 请求 | 实测 |
| --- | --- | --- |
| 1 | `GET /v1/models`（A client key） | 401 |
| 2 | `GET /api/status`（A admin token） | 401 |
| 3 | `GET /api/config`（A admin token） | 401 |
| 4 | `POST /api/config/save`（A admin token） | 401，且 B 的 `gateway.local.json` 哈希未变 |
| 5 | `POST /api/keys`（A admin token） | 401 |
| 6 | `POST /api/config/reload`（刷新） | 401 |
| 7 | `POST /v1/responses`（A client key） | 401 |

结果：**7/7 全部 401**，`bConfigUnchanged=true`。
控制组：B 用自己的 admin token `GET /api/status` → **200**，只看到自己的 `tenant-b-upstream` 与 `MARKER-TENANT-B`。
记录隔离：B 的 `/api/logs`、`/api/config`、磁盘 `stats.json` 不含 A 标记或 A 的 client key；A 的 status/`stats.json` 不含 B 标记。目录层面 A/B 互不含对方 client/admin 凭据（`keys.local.json` 各自加密存储）。
脱敏片段（B 自己的日志）：

```text
{"lines":["[info]  管理 API 已启用令牌保护（MG_ADMIN_TOKEN）","[info]  model-gateway 已启动: http://127.0.0.1:18883  (健康检查 /healthz, 控制面板 /)"]}
```

含义：**当前产品的"多用户"模型是"每人独立实例"**（独立端口 + 独立 `MG_CONFIG_DIR` + 独立凭据）。在该模型下，凭据、配置、Key、统计、日志、视频任务均随实例隔离，跨身份访问一律 401；不存在可用的跨用户读写面。

### 5.2 单实例内多租户（**GAP_NOT_IMPLEMENTED**，如实记录）

`MG-R009` 的"双用户/双身份"若理解为**同一实例内的两个租户**，当前实现不支持，证据：

- `src/` 中除 `src/tenancy/**` 外**没有任何** `tenancy` / `requireUserScope` / `createScopeStore` 引用（脚本逐文件扫描，`tenancyWiringFiles=[]`）；`src/tenancy/*` 是未接线的库（离线单测在 `agg-tenant-isolation.test.mjs`）。
- 数据面鉴权只有一把全局 `MG_CLIENT_KEY`（或匿名），管理面只有一把 `MG_ADMIN_TOKEN`：没有第二身份角色。
- 请求带 `x-mg-scope: tenant-a` / `x-mg-tenant: tenant-a` 时响应与不带时**字节一致**（`tenantHeaderIgnored=true`），即没有作用域维度。
- 唯一的"主体"维度是 F04 视频幂等（`src/index.js:1301`，主体 = client key 的 sha256 前缀），仅用于任务幂等/可见性，不是租户边界；配置、Key、统计、日志不按主体分域。

这不是"测试未通过"，而是**该维度未实现**。若所有者需要"单实例多租户"，最小可执行改法（`src/tenancy/*` 已具备原语，缺接线）：

1. **配置 schema**：新增 `tenancy: { mode: 'multi', scopes: ['tenant-a','tenant-b'] }`；单用户缺省仍为 `single`（行为不变）。
2. **身份解析**（`src/index.js` 数据面入口）：把全局 client key 升级为"per-scope key 映射"（`keys.local.json` 增加 `scopeId` 字段，或独立 `scopes.json`）；请求进来先用 key 反查 actor → `requireUserScope(actor, { config })`，拿不到 scope 即 401/403。
3. **存储分域**：`state.paths` 换成 `createScopeStore(cfgDir, { config }).forScope(scope)`：`gateway.local.json`/`keys.local.json`/`stats.json`/`videos.json` 与日志文件全部落 `cfgDir/<scopeId>/…`。
4. **管理面**：`requireAdmin` 之外增加 scope 断言；跨 scope 的资源读写返回 **403**（已存在但无权限）或 **404**（不泄露存在性），与本任务验收要求一致。
5. **观测/日志**：`recordTerminal`/`log.info` 事件增加 `scopeId` 字段，日志按 scope 分文件；`/api/status` 只返回当前 scope 的 provider/模型。
6. **迁移**：既有单用户配置在 `single` 模式映射到 `local` scope（`src/tenancy/scope.js` 已实现），启动时一次性迁移或直接按 `local` 读取，避免破坏现有用户。

改动面估计：`src/index.js` 5 处接线 + `src/router.js`（配置路径）+ 配置 schema；`src/tenancy/*` 不需要改。**需 Lead 决策后再动 `src/**`**，本任务未改共享代码。
