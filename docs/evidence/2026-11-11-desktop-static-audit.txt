Desktop 静态审计（2026-11-11）：版本与 CODEX_HOME 支持
=====================================================

> 目的：在**不打扰正在运行的 Desktop 会话**的前提下，记录可核实事实，避免把 CLI 证据当成 Desktop 结论。

## 现场

- Desktop 进程在运行：`/usr/lib/chatgpt/ChatGPT`（已运行约 4h42m），另有 crashpad 子进程。
- 因此本轮**不启动第二个实例、不做 GUI 端到端**（避免抢单实例锁/干扰用户会话）。

## 版本事实（关键）

| 组件 | 版本 |
| --- | --- |
| Codex CLI（harness 入口） | `0.167.0` |
| ChatGPT Desktop 内置 codex | **`0.167.0-alpha.3.2`** |
| ChatGPT Desktop 应用 | `26.1103.32239` |

结论：Desktop 用的是 **alpha 构建**，与 CLI 不是同一二进制；CLI 上的聚合行为不能自动外推到 Desktop，
任何 Desktop 端到端验收都必须在该 alpha 构建上单独执行并留证。

## 配置面

- 内置 codex 二进制里 `CODEX_HOME` 出现 68 次（字符串统计），支持自定义 home。
- 因此“独立 CODEX_HOME 起第二个 Desktop 实例”在机制上可行，但需要 GUI 会话与独立登录数据，
  且会与当前运行实例共享桌面环境；本轮按安全优先未执行。

## 与既有证据的关系

- 2026-11-09 证据已记录：Desktop 的 app-server 协议支持 per-thread `modelProvider`，
  但 Desktop 创建线程时传 `modelProvider:null`，模型列表无 provider 过滤、UI 无 profile 选择器。
- 本轮的静态审计进一步说明：即使未来协议支持，也要面对 alpha 构建与 CLI 的差异。

## NOT_RUN / 边界

- Desktop GUI 端到端（同会话切换、目录显示、v2）：NOT_RUN。
- 第二个 Desktop 实例（独立 CODEX_HOME）：未执行（避免干扰运行中的用户会话）。
- 若所有者授权，可在关闭当前 Desktop 后用独立 CODEX_HOME 做一次受控验收，需单独的登录与回滚步骤。
