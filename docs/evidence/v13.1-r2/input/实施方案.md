## 1. 产品合同与不变量

普通用户通过「应用接入 → 模型服务 → 模型池」或「添加服务 → 选择模型 → 建池 → 接入应用」完成配置，日常使用自己的 Harness，不必天天打开网关。一级导航固定六项：应用接入、模型服务、模型池、用量分析、稳定性策略、设置；高级模型目录、手动路由、客户端密钥、请求日志按需展开。电脑宽屏左侧导航、工作区填满、主从列表独立滚动、长名称不撑破、面包屑可点击、返回保留位置。禁止把任何模拟数据、探活成功、配置写入当作真实调用或实际生效。禁止静默降级、偷偷换身份/模型/协议、丢工具、重放副作用；明确授权的兼容池内切换例外，必须有收据。官方直连完全走原生官方；纯路由不使用 GPT 套餐；聚合官方父模型 + 第三方子模型，保留原生父子调度与原生压缩。网关不是新的 Agent 调度器。套餐只通过允许的认证和使用方式接入，不复用未经授权的凭据或跨身份绕过限制。未经明确授权不得下载重依赖、模型权重或更改生产；依赖先检查已安装版本。Node >=24、当前零第三方运行时 npm 依赖优先保持。

## 4. 目标架构与数据模型

沿用 Node.js >=24 / ES modules，优先扩展 `src/ui-next` 的 api/store/router/components 和现有服务端模块；`src/ui-demo` 作为原有参考，V13 与 V13.1 存档。V13.1 的视觉样式应抽取成共享设计令牌与组件，不复制多层 CSS override。新 UI 先独立 preview 路径/实例（如 `/ui-vnext`，提案）；生产 `/ui-next` 保持可回滚，未验收不切根路由、不重启 8787。避免把 266KB 原型、多个 render/dispatch 覆盖带入生产。组件建议 `shell`, `router`, `store`, `api`, `resources`, `pages/{apps,services,pools,usage,reliability,settings}`, `components/{table,dialog,form,status,empty,error,toast,scroll}`, `advanced`，统一 design tokens；无大型框架迁移除非有证据并授权。

控制面：可编辑配置 GET `/api/config`，运行状态 GET `/api/status`，凭据独立 `/api/keys`，版本/代际校验；后端是唯一真源，前端保存非敏感偏好/草稿，不能持有秘密、consent token 不落盘。重用现有 config transaction（原子写、journal、备份、409），先完成影响分析、预览和确认，再事务写入与重建运行时。部分成功必须可重试并报告明确阶段。

资源模型（设计提案）：

- `ProviderTemplate(templateId, version, region, authKind, baseUrl, protocol, discovery, docs, evidence)`：公共静态模板，不包含账户密钥。
- `Service(serviceId, templateId?, displayName, region, endpoint, enabled)`：独立实例，一个模板可多实例。
- `Connection(connectionId, serviceId, credentialRef, identityDomain, quotaScopeId, enabled, priority, maxConcurrent)`：密钥引用、合法授权，运行状态分离。连接权限关联表 `ConnectionModel(connectionId, modelId, availability, capabilityEvidence)`。
- `Model(modelId, serviceId, upstreamModelId, displayName, capability, api, enabled, metadataProvenance)`：稳定 ID，模型能力与授权独立。候选身份至少 `(serviceId, modelId)`；选择时追加连接 ID。名称不参与引用。
- `Pool(poolId, slug, name, enabled, selection, recoveryPolicyRef, revision)`，`PoolMember(poolId, modelId, priority, weight, enabled, constraints)`：稳定 slug，成员独立生命周期；底层优先扩展 virtualModels，不维护重复路由系统。旧虚拟模型和 defaults.directory 迁移预览，不擅自改变既有策略。
- `HarnessBinding(harnessId, instanceId, mode, roleTargets, policyRef, desiredRevision, appliedRevision, verifiedRevision)`：roleTargets 是 tagged union `{kind:'native'|'model'|'pool', id}`。应用与池多对多通过角色引用；一个池被多个应用使用。
- `Policy(scopeType, scopeId, overrides, revision)`、`RuntimeHealth`、`UsageEvent`、`ConfigRevision`、`Operation`：分别处理配置、健康与审计。

映射：纯路由父/子同一池别名（可扩展角色策略但不默认改），聚合官方父保留 + 子池；直连不经过池。`mg-pool-<stable-id>` 仅提案，需验证 Codex 模型目录命名、保留前缀、冲突与身份分类；不允许未知 mg-* 自动走默认上游。池目录能力采用候选共同可安全满足的能力或按角色/请求过滤；上下文/原生压缩阈值与候选真实能力保持一致，不能夸大最大窗口。新会话选择候选；已开始会话保留原模型、账户、协议、上下文与配置代际，除非经证实安全可迁移且获明确授权。在途请求不受池编辑干扰。若删除/暂停最后可用目标，说明受影响应用并引导更换、解绑；允许明确停止管理而非永久卡住。保留历史用量、日志 ID/名称快照和回滚版本（失效时提示）。

## 5. 管理 API 接线与建议新增契约

所有新接口名为设计建议，先评审与现有 `/api/aggregation/*`、`/api/config/save` 的兼容，禁止重复造 CRUD。资源级命令可在现有事务上薄封装。每个写请求包含 `expectedVersion`（适配既有 version）、必要的 requestId/幂等标识；错误统一 `{code,message,details,retryable,currentVersion,traceId}`（兼容旧信封）。明确 400 参数、403 来源/授权、409 冲突、422 不可配置、428 待确认；旧客户端保留。

| 操作 | 现有/建议接口 | 关键约束 |
|---|---|---|
| 启动 | 既有 GET config/status/modes/health；建议 GET `/api/capabilities` | capability/feature/version/evidence；分区 loading/error/stale |
| 模板查询 | 建议 GET `/api/provider-templates` | 本地版本、category/region、查询/分页，官方来源与发现支持 |
| 添加服务 | 既有 config/save + keys + aggregation providers/sync；资源命令可薄封装 | 模板→授权→模型发现，部分失败可继续，不自动入池 |
| 修改/删除影响 | 建议 POST `/api/config/preview` + existing save/事务 | 资源、池、应用、在途、凭据与回滚影响；预览代际绑定，确认时重验 |
| 连接认证/发现 | 建议 `/api/connections` CRUD、`/:id/authorize`、`/:id/discover`、`/:id/health` | 支持实际认证的模板开放；OAuth/Key 不回显；真实探测有费用提示 |
| 池 CRUD | 扩展 config 中 virtualModels 或新增 `pools` 映射；统一持久化与校验 | 一套源，不把 V13 前端 state 当事实；旧 config 可读写兼容 |
| 生效策略/模拟 | 建议 `/api/policies/effective`、扩展 `/api/route-preview` | 作用域/来源/上限/不兼容原因、模型与连接预算，纯决策无真实调用 |
| 应用接入 | 扩展 existing switch/rollback/reconcile，建议 adapter registry `/api/harnesses` | preview 428 无写；consent/expectedSha 确认；漂移 409，重启后实际检测，禁止读写 auth.json 内容 |
| 异步操作 | 建议 GET `/api/operations/:id` + 取消命令（支持才开放） | 进行中/部分成功/完成/失败/取消；持久化必要进度；不伪造取消已提交操作 |
| 用量日志 | 既有 model-stats/native-usage/logs/status；建议结构化分页查询 | 统一单位、真实时间桶、来源/维度，未知不填零 |
| 备份恢复 | 建议 `/api/config/backups` 与 import preview/apply | 脱敏、schema/version、三方差异、重新授权；不覆盖原始用户配置 |

每条接口必须给出 schema、权限、字段来源、错误、幂等/并发语义、验收 fixture、真实收据和前端状态映射。连接/模型同步结果分 `added/updated/removed/unavailable`，用户覆盖不丢失。切换回滚不可仅变 UI 内存。

## 6. 可靠性设计：统一一个请求预算

### 6.1 现状与映射

参考配置：retry.maxAttempts=3 含首发，initialDelayMs=500、maxDelayMs=8000、jitter=.2；timeout.connectMs=15000、firstByteMs=90000、idleMs=60000、loopMs=120000（默认）、overallMs=0（不限）；maxPerProvider=8；affinityTtlMs=300000；failbackProbe.enabled=true/everyMs=30000/successStreak=2；provider.circuit 示例 maxFailures=3/openDurationMs=10000。Codex maxSameProviderAttempts=1（额外重试）、maxFailovers=2、maxTotalAttempts=3、maxWaitMs=30000。`src/retry-policy.js` 429 单次默认等待上限 30s，业务错误/限流归因与熔断分离；`src/forward.js` 旧有模型循环。实际值须读取真实配置，不直接覆盖用户已有参数。

V13 预设是产品提案，不是现行后端参数。正式实施的起始调优候选（日常/长任务/响应优先）：每候选额外重试 3/5/1，Codex 2/5/1；账户切换 5/10/2，模型切换 10/20/5；全链发送总次数 24/60/10；循环 2/3/1（Codex 原型当前限制 1，需另行验收才允许多轮）；故障恢复预算 180/600/30 秒，整池时间 300/900/60 秒，续传尝试 5/10/2（仅支持协议），正常长生成整体硬超时默认不限。建议数值输入范围沿 V13，真实默认必须根据本地实际网关长任务、服务限流、费用与恢复效果验证；不将 60 次自动用于不可重试请求。

### 6.2 生效策略合并与状态机

优先级不是简单全覆盖：全局推荐 → Harness/角色显式偏好 → 池配置（只负责选择与回退偏好），服务/连接/模型的容量、额度、能力、用户授权与安全限制为硬约束，所有相关预算取可用最严上限；单次请求总期限覆盖排队、建连、响应头、流式、等待、恢复；另有故障阶段预算避免正常长任务中断。UI 展示实际有效值及来源，修改不影响已经固定代际的在途请求。禁用能力、身份域、危险重放为不可覆盖底线。

统一 request ledger：首次发送 + 各上游尝试、账户/模型切换、轮数、时间与金额计数；取消即停止，避免 `request.js`、`forward.js`、Codex 决策器各自重试相乘。顺序：资格过滤 → 选候选/连接 → 发送 → 错误及阶段分类 → 安全原目标重试/等限流/授权账户切换/兼容模型切换/可恢复错误有界循环 → 终态。根据类型选择跳过而非每种错误都重试：401 需重新授权，400 请求错误停止，明确额度耗尽跳过整个共享额度域，429 等 Retry-After 或授权换独立域；Retry-After 超预算不能缩短后强行发送；网络未知提交状态、已交付流、工具副作用、部分提交或加密上下文不可读禁止危险重放；有原生恢复协议时优先保持原目标。恢复探活应受授权/频率限制，失败不误记用户逻辑请求，真实上游可能计费；不宣称免费。熔断半开与回切探活协作。固定/指数退避、抖动、并发、排队和冷却用同一时钟/取消信号。

## 7. 页面交互规格与取舍

- 应用接入：已管理/检测/规划分组；首屏显示当前模式、目标、是否实际生效、下一步。三模式草稿跨页；池/模型选择、有效策略、预览应用、回滚、解除管理。规划 Harness 不可假装可用，通用 API 接入提供复制地址/模型标识及权限说明。无需显示 SHA/token/配置文件路径（诊断可展开）。
- 模型服务：我的服务与服务目录；明显添加/自定义/编辑/暂停/删除；连接与模型子页搜索/排序/长列表；目录按区域/套餐/API/本地/云筛选，自动填参，凭据单字段与安全授权，模型发现和差异预览；有真实费用的测试另确认；多账户高级项默认折叠。
- 模型池：左列表独立滚动、右详情（候选/策略/应用引用/预演），可创建时选候选，搜索保留选择，批量启停/加入/删除影响预览，优先级/权重仅相应策略展示；展示可配置数与实际可运行数，不能混用。应用池双向绑定统一保存。
- 用量：网关请求与原生本地用量明确区分，逻辑请求/上游尝试/成功数、输入输出/缓存 token、时间范围、服务/模型/池/应用（后端有才显示）、未知费用/额度显示未读取，不推算套餐剩余额度，CSV 防公式注入。
- 稳定性：默认三个预设及当前范围，显示真实生效摘要；详细参数分重试限流、候选熔断、超时续传；仅支持字段可编辑，未实现标规划。单应用/池覆盖提供恢复继承，数值范围、单位、冲突及时解释。
- 设置：主题密度、本机服务状态、备份导入导出、通知、打开高级管理；高级模型与路由避免与普通模型池形成冲突，明确哪个规则生效。日志从故障入口直达过滤后的详情；不让普通用户修改无意义的底层参数。
- 通用：固定导航与顶部工具栏，弹窗内部滚动与底部操作固定，列表空/错/加载/分页/长名/全选；焦点返回、键盘 Tab/ESC、缩放 100/125/150/200%、中英文长文本、滚动位置、可点击面包屑、浏览器前后退、深浅主题、通知非阻塞；不做移动端优先，不以大面积留空换整齐。高级功能、错误详情逐级展开。

## 9. 测试与验收（不是仅冒烟）

### 9.1 分层与环境

- 静态/契约：`npm run check`、`npm run docs:check`、`npm run contract:check`，Node>=24 已有版本先检查；`npm run test:offline`、`npm run matrix:v2`、`npm run gate:v2`、`npm run gate:v2:independent`、`npm run release:freeze`（脚本存在于基线 package.json，实际执行结果记录，不得假称通过）。
- 隔离真实 HTTP：启动独立 ModelGate 与可控 HTTP/SSE fixture，真实浏览器通过 origin 请求真实后端配置/路由，记录网络、文件与进程；此层是 integration/fixture，不等同真实厂商。与生产 HOME、端口、keys、日志隔离，不自动读取秘密，不装重依赖。
- 真实厂商/真实原版 GUI：仅用户授权的成本/模型/账号，真实请求与 native GUI；GPT 测试仅 `gpt-6-luna`，Go 首轮仅 DeepSeek V4.1 Flash，其他真实付费模型/服务需要单独授权。无权限标 BLOCKED，不换其他 GPT；多个真实候选不足时故障链先用 HTTP fixture 验证，真实多模型结论待授权。禁止用 Codex 模拟客户端代替原版 GUI；CLI 证据可辅助但不替代。原生压缩必须由 Codex 实施，不自建压缩。
- 每份证据 pin commit SHA、环境/模型/协议、操作命令、配置代际、脱敏请求 trace、预期/实际、PASS_REAL/PASS_MOCK/FAIL/BLOCKED/NOT_TESTED；只在已执行层标通过。使用现有 MG-R001..R012 门禁，不降低。
