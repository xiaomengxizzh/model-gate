## 4. PR #2 独立审计（不合并结论）

- 分支：`feature/codex-opencode-go-adapter-20261107`，6 提交，`src/codex-responses.js`(208) + `src/codex-handler.js`(86) + `tests/codex-responses.test.mjs`(88)，并删除 main 上的 4 份计划文档（分叉残留）。
- 可取之处：零依赖、`422` 拒绝无法保真的输入、`custom` 工具映射思路、`call_id` 保留、隔离默认关闭、429 不做内部放大。

**阻断性缺口**：

1. **绕过治理**：模型带 `quota/dailyQuota/maxContext/fallbacks` 或存在任何 `virtualModels` 时直接 `422`，与「Responses 必须进入既有鉴权/配额/路由/统计/熔断」冲突。
2. **旁路路由**：自建 `forward` 调用与 header 构造，不走 `forwardChain`（无熔断、无亲和、无统计、无并发/限流、无跨模型兜底）。
3. **无记账**：不写 token/usage、不记 provider/model 统计，费用与配额不可观测。
4. **SSE 顺序不完整**：工具项在流结束才一次性 `output_item.added`，缺 `function_call_arguments.delta` 的逐段语义；消息项 `output_index` 依赖 `find()`，多次内容/工具混合时顺序不稳。
5. **事件契约风险**：`response.created` 只在首内容/结束时发；无 `response.in_progress`；无 `response.failed` 之外的终态保障。
6. **配置耦合**：`codexWire`/`codexChatPath`/`codexResponsesPath` 自定义字段，未进入管理面契约，前端不可见。
7. **测试是 mock 单测**：不覆盖鉴权/虚拟 Key/额度/429 预算/断流/取消。

**裁决**：**拒绝直接合并**。其转换器思路已在 G2 重写吸收（独立实现、无复制风险），PR #2 由 owner 关闭或改作历史参考。
