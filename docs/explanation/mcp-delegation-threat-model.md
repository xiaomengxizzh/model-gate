# MCP 委派威胁模型（OpenCode Go 外部 worker）

关联契约：[本地 MCP 委派契约 v1](../contracts/modelgate-mcp-delegation-v1.md) ·
当前实现状态：**只有契约与 fixture，没有运行时代码**（G2 交付，G3 才实现）。

## 0. 结论先行

| 问题 | 答案 |
| --- | --- |
| 这是不是 Codex 原生子代理？ | **不是**。这是工具驱动的外部 worker 委派（§1.2） |
| ModelGate 是否接触 ChatGPT 凭据？ | **不**。不读 `auth.json`/`CODEX_HOME`，不代理 `chatgpt.com`，不持有订阅 token |
| Go 凭据会不会回到模型？ | **不会**。只在进程内用于发请求；结果、任务表、日志都不含 |
| 模型能不能自己指定上游？ | **不能**。provider/model/URL/host/凭据只来自服务端配置 allowlist |
| V2 密文怎么处理？ | **fail-closed**：跨域前拒绝，不解密、不改写、不静默删除、不降级 V1 |
| 结果可信到什么程度？ | 有 `resultDigest` + 产物 sha256 复算；**没有**密码学签名，防的是实现漂移与工作区内容不一致，**不防**同机攻击者（§6） |

## 1. 系统与信任边界

### 1.1 进程与数据流

```text
┌─────────────────────────────┐        ┌──────────────────────────────────┐
│ Codex CLI/Desktop（用户自带）│        │ OpenAI 官方服务                  │
│  父模型 gpt-6-luna           │───────►│  GPT 父模型请求直连，不经 ModelGate│
│  本地工具调用 ──stdio─────────┼──┐     └──────────────────────────────────┘
└─────────────────────────────┘  │
                                 ▼
                    ┌───────────────────────────────┐
                    │ ModelGate MCP server（本机）   │
                    │  · 参数 allowlist / 归属校验   │
                    │  · 任务状态机 + 幂等 + 持久化  │
                    │  · 结果脱敏 / 产物复算哈希      │
                    └───────────────┬───────────────┘
                                    │ 复用既有 Go provider 发送链
                                    ▼
                    ┌───────────────────────────────┐
                    │ OpenCode Go（deepseek-v4.1-flash）│
                    │  只收到 Go 自己的凭据与会话头    │
                    └───────────────────────────────┘
```

### 1.2 诚实表述（写文档/回执时的硬要求）

必须写：

> 通过本地 stdio MCP 工具把任务委派给外部 OpenCode Go worker；属于**工具驱动的外部委派**，
> 不是 Codex 原生 `spawn_agent` 跨 provider 子线程；没有原生 child thread、没有父子会话继承。

禁止写（出现即视为错误结论，需要在同一次交付里更正）：

| 禁止表述 | 为什么是错的 |
| --- | --- |
| "原生跨供应商子代理已打通" | 客户端不创建该子线程；子代理只是外部 worker |
| "Codex 会把子任务当自己的孩子线程" | 父子关系只存在于 ModelGate 的任务记录里 |
| "等同 spawn_agent，只是换了个 provider" | 等待/追派/进度/取消语义完全不同，靠 MCP 工具模拟 |
| "子任务在 Codex 会话历史里" | 不在；历史只在 ModelGate 任务表与工具结果里 |
| "HTTP 200 就算闭环" | 闭环要求父端拿到工具结果并正常结束（方案 §5） |

同时必须写清"这是降级路径"：工具结果带 `delegation.native=false`、`delegation.degraded=true`，
父端与审计方据此知道它不是原生能力；任何 `native:true`/`degraded:false` 的宣称都应被拒绝
（与 [UHR 契约 §P06](../contracts/uhr-mcp-v1.md) 的 `isNativeDelegationClaim` 同一原则）。

## 2. 资产

| 资产 | 位置 | 后果 |
| --- | --- | --- |
| Go API Key | ModelGate 配置/环境变量，仅进程内读取 | 泄漏 = 消耗用户 Go 额度、被冒用 |
| Codex 登录态（`auth.json`） | 用户主目录 | **本契约完全不接触**；一旦接触即为认证边界越界 |
| 任务正文 / 结果正文 | 内存（正文不落盘）、结果文本落任务表 | 泄漏 = 用户代码/意图外泄 |
| 工作区文件 | 别名根下的真实文件 | 越界读写 = 数据损坏/凭据外泄 |
| 任务表 `tasks.json` | `<config>/delegation/` | 篡改 = 状态伪造、重复派发 |
| 上游额度 | OpenCode Go | 重复派发 = 白烧额度 |

## 3. 信任边界与对手模型

| 边界 | 谁能越过 | 本设计承认的前提 |
| --- | --- | --- |
| Codex ↔ MCP server | 同 OS 用户下的任意进程都能起同名 stdio server | 用户对自己的账号负责；本服务不做跨用户鉴权 |
| MCP server ↔ 任务表 | 同 OS 用户可读 `0600` 文件（同用户即同权限） | **不防**同用户恶意进程；只防"另一个配置目录/另一个实例"误读 |
| MCP server ↔ Go 上游 | 需真实 Key（不落盘、不回显） | Key 泄漏面 = 进程内存 + 用户自己的配置 |
| 模型输出 ↔ 工具参数 | 模型完全控制 arguments | **所有**边界校验必须假定参数是敌意的 |

结论：本威胁模型的防御对象是**被提示词注入或幻觉驱动的模型**，以及**实现自身的漂移 bug**；
不承诺抵御已经拿到同 OS 用户权限的攻击者。

## 4. 威胁与缓解

| # | 威胁 | 缓解（契约锚点） | 残留风险 |
| --- | --- | --- | --- |
| T1 | 模型在参数里塞任意 URL/host，把服务变成 SSRF 跳板 | 目标键检测 + 服务端 allowlist（契约 §8.2 优先级 3、§8.1） | 配置里若填了恶意 baseUrl，仍会连过去（配置是用户信任输入） |
| T2 | 模型在参数里塞凭据/请求头，覆盖 Go 认证 | 凭据键检测（§8.2 优先级 2）+ 发送层恒用服务端凭据 | 无（参数无法进入头构造） |
| T3 | 任务正文里夹带凭据，被落盘或回显 | `MCP_SECRET_IN_ARGUMENT` 拒绝（§8.2 优先级 6）；正文不落盘（§10）；结果脱敏 | 变形编码的密钥不保证识别（只按形状匹配） |
| T4 | V2 密文被解密/改写/删除/降级 | 键级 `MCP_V2_OPAQUE`、跨域前拒绝（§8.2 优先级 1） | 值级密文（base64 放进合法字段）不会被识别——**设计边界**，见 §5 |
| T5 | Go Key 出现在工具结果/日志/任务表 | §8.5；结果只含 provider/model/统计；日志白名单字段 | 上游错误体若含 Key，必须靠映射表丢弃原文（§9 末段） |
| T6 | 跨 owner / 跨任务读取他人任务 | ownerRef 派生 + 归属判定表（§7.3），失败不泄露字段 | 同 OS 用户可读任务表（§3 前提） |
| T7 | 重放导致重复派发（白烧额度、重复副作用） | `idempotencyKey` + 规范化摘要（§6）；"上游请求数不增"作为验收判据 | 客户端换了 key 就等于新任务（这是调用方的选择，不是漏洞） |
| T8 | 父进程重启后重复创建任务 | 恢复流程要求先 `get`/`wait` 对账（§5.3）；`UNKNOWN` 禁止重发（§5.2 禁止转移） | 依赖客户端遵守"先查后建"；服务端只能靠幂等键兜底 |
| T9 | 等待超时被当成任务失败，导致误判/重复派发 | `timedOut` 与 `state` 分离（§5.4）；等待不改状态 | 客户端若忽略 `timedOut` 字段仍会误判（文档职责） |
| T10 | 伪造产物哈希，谎称"跑过了" | 哈希由 ModelGate 复算（§4.6），不复用 worker 自报 | 复算只证明"文件现在是什么"，不证明"是 worker 写的" |
| T11 | 取消被假装成功 | `cancel.reachedUpstream` 三态（§3.6）；`UNKNOWN` 拒绝取消 | 上游不确认时只能停在 `null`（诚实但不确定） |
| T12 | 任务表被截断/损坏导致状态倒退 | 原子写 + 单写者锁 + 损坏即 fail-closed、不自动重置（§10） | 磁盘损坏仍需人工介入（设计选择：宁可停也不猜） |
| T13 | 把"外部委派"包装成原生子代理，误导验收方 | `delegation` 常量字段（§4.2）+ §1.2 的表述要求 | 文档纪律，无法技术强制 |
| T14 | 结果回执在传输/实现中被改写 | `resultDigest`（§4.4）覆盖结果正文与产物 | 无签名：同机攻击者可同时改结果与摘要（§6） |
| T15 | 任务正文/结果正文进日志 | 日志只写白名单字段（§8.5） | 实现若打 debug 全量 body 即违约，需代码评审兜底 |

## 5. V2 密文 fail-closed：精确边界

只做三件事，且都不涉及"理解密文"：

1. **拒绝**：任意层级键名命中 `encrypted_content`/`encrypted_task_id`/`encrypted_payload`/`opaque_v2`
   ⇒ `MCP_V2_OPAQUE`，零提交（契约 §8.2 优先级 1）。
2. **不碰**：不解密、不重编码、不改写、不删除、不"用明文替代后继续"。
3. **不降级**：不因为读不到密文就自动切 V1 或改用别的通道。

明确的设计边界（**不是 bug**）：

- 检测只看**键名**，不扫描字符串值的语义。把 base64 密文放进 `task` 正文的合法位置不会被识别；
  这是为了避免误伤（普通代码/哈希/证书片段容易被误判）以及避免"猜内容"的诱惑。
- 从上游返回的结果正文不按密文规则二次解析：它只是不透明文本，原样（脱敏+截断后）返回，
  由父模型自己决定怎么用。网关**不会**因为结果里出现密文形状就尝试解读。
- 相关背景与本仓库既有结论一致：[Codex v2 子代理边界](codex-v2-agents.md)、
  [M2 明文委派路径评估](m2-plaintext-redelegation-options.md)。

## 6. 结果回执完整性：能证什么、不能证什么

- `resultDigest` = 对 `{artifacts, model, provider, resultText, taskRef, turnRef}` 的 canonical sha256。
  ACK 只改 `state`，**不影响摘要**，所以 ack 前后可复核同一条结果（契约 §4.4）。
- `artifacts[].sha256` 是 ModelGate 对工作区文件的**复算值**，不采信 worker 自报。
- 能证明：父端拿到的就是服务端当时记录的那份结果；产物与服务端此刻读到的一致。
- **不能**证明：结果来自真实的 Go 上游（没有上游签名）、结果未被同机攻击者同时改写（没有密钥）、
  worker 真的执行了声称的命令（只能证明最终文件状态）。这一层需要真实上游验收与进程隔离，不在本契约范围内。
- 因此文档与回执不得写"密码学证明""不可伪造回执"。

## 7. Go Key 隔离的具体约束

| 项 | 约束 |
| --- | --- |
| 来源 | 复用既有 provider 配置/环境读取路径；不新增第二套凭据来源 |
| 使用 | 只在发送层构造认证头；MCP 层**没有**读取 Key 的 API |
| 落盘 | 不写任务表、不写日志、不写 fixture、不进 Git |
| 回显 | 结果只有 `provider`/`model` 字符串；无 `keyRef`/掩码/前后缀 |
| 会话头 | 复用 `x-opencode-session` 的 HMAC 派生（不转发原始 Codex session/thread id） |
| 错误路径 | 上游 401/403/402 统一映射为 `MCP_UPSTREAM_AUTH_FAILED`，**丢弃上游错误体原文** |
| Codex 侧 | 不读、不复制、不改写 `~/.codex/auth.json` 与 `~/.codex/config.toml` |

## 8. 日志与脱敏

- 允许字段：`taskRef`、`turnRef`、`state`、`provider`、`model`、`elapsedMs`、`resultBytes`、错误码、
  `tool`、`waitedMs`、`timedOut`、`duplicate`。
- 禁止字段：任务正文、结果正文、`params.arguments` 原文、请求头/响应头、上游 body、Key、绝对路径。
- 结果正文返回前的脱敏：凭据形状 → `[redacted]`，并记录 `RESULT_REDACTED` lossy。
- 复用既有 secrets 词表热更新（MG-005）作为第二道兜底；但**不依赖**它作为唯一防线。

## 9. 残余风险总表

| 风险 | 等级 | 处理 |
| --- | --- | --- |
| 同 OS 用户可读任务表与结果文本 | 中 | 接受（同用户即同权限）；`0600` + 单写者锁降低误伤 |
| 值级密文/编码后的密钥不被识别 | 中 | 接受为设计边界；靠结果脱敏与配置 allowlist 兜底 |
| 无上游签名，无法证明真实性 | 中 | 只声称"服务端记录一致性"；真实验收另立 |
| 客户端不遵守"先查后建" | 中 | 幂等键兜底；文档要求写在契约 §5.3 |
| 配置被写入恶意 baseUrl | 高（若发生） | 配置属用户信任输入；Go 入口 host 白名单（既有 `isOpencodeGoHost`）仍生效 |
| 实现日志打全量 body | 中 | 契约 §8.5 明文禁止；需代码评审与测试（AC-9） |
| 取消停在 `null`（未确认） | 低 | 如实回显，不假装成功 |
