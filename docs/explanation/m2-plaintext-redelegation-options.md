# M2 可选路径评估：v2 加密任务与跨供应商子代理（2026-11-11）

> 状态：**设计备忘 / 未实现**。当前 M2 按 D3 主动阻断（见 [LIVE 取证](../evidence/2026-11-11-e4-v2-live-blocked.md)）。
> 任何实现都需要所有者对该具体路径的单独授权。

## 事实基线（已实测）

- 官方主代理可以 `spawn_agent` 出第三方子代理；`model` 覆盖生效。
- 子代理请求携带 `agent_message` 的 `encrypted_content`（以及可能的 `encrypted_task_id`），网关按 D3 返回显式 `v2_encrypted_task_unsupported`，主代理如实回显。
- 因此阻断点不是路由/身份/模型解析，而是**任务内容不可读**。

## 可选路径

| 路径 | 做法 | 前提 | 结论 |
| --- | --- | --- | --- |
| A 客户端明文委派 | 客户端生成任务时使用可读文本（或提供关闭加密的受支持开关） | 需要 Codex 官方支持；0.167 的 v2 message 参数标注 encrypted:true | 唯一不触碰密文的路径；**无公开开关证据**，暂不可行 |
| B 网关受控改写 | 网关把加密任务替换为可读文本 | 必须知道明文 | D3 明令禁止猜测/伪造/删除密文；**否决** |
| C 子代理走原生 Responses | 第三方上游原生理解该密文 | 需要原生 Responses 且能解密的第三方 | 现无此类上游；**不可行** |
| D 使用 v1 协作命名空间 | v2 关闭时 multi_agent_v1 为旧式任务 | 需确认 v1 spawn_agent 是否也加密、是否支持 model 覆盖 | **未取证**；且计划 D3 禁止默认全局切回 v1，只能作为显式产品决策 |

## 建议

1. 保持当前行为：显式阻断 + 主代理可见错误（已具备，且有回归与 LIVE 证据）。
2. 若所有者希望推进，先做一次**只读取证**：在隔离环境抓取 v1 spawn_agent 的 schema 与真实任务 payload，判断是否明文、是否有 model 覆盖；该取证不改变产品行为。
3. 只有在（1）v1 任务确为明文且（2）所有者明确同意以 v1 作为 M2 路径时，才进入实现与验收；实现范围应限制为显式选择 v1 的会话，不得全局默认。

## 验收标准（若获授权）

- 主代理创建第三方子代理后，子代理收到完整可读任务并完成允许的工具调用，父线程拿到结果；
- 全链路无密文解析/伪造；失败仍返回显式错误；
- 离线回归 + 一次真实 LIVE 证据；Desktop 与真实 v2 仍分别标注。

## 明确不做

- 不尝试解密/重放密文；
- 不静默把会话切到 v1；
- 不把子代理能启动当作 M2 完成。
