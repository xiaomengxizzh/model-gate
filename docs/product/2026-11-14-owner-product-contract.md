## 0. 唯一产品成功定义

一个普通用户打开 **ModelGate GUI**，选择 **聚合模式**，添加 **OpenCode Console 或 OpenCode Go Provider**、完成自身的必要授权，ModelGate 自动发现并提供该账号授权范围内的**全部可用 OpenCode 模型**；用户打开**原版 Codex Desktop GUI**，在同一模型选择入口自由使用其现有 **ChatGPT 套餐**模型和全部已添加的 OpenCode 模型；不被迫手改 TOML、维护目录、手动部署角色配置，也不损失原生 Codex Agent/工具/会话/子代理协作能力。还应支持以 GPT 父模型与 OpenCode 子模型进行完整原生父子协作。

“全量”指按用户自身账户实际可使用的模型动态发现与正确呈现；遇到官方接口缺失或目录超限，不可静默删模型，必须有完整清单、诊断、可执行的兼容办法和验收。不得伪造上游模型能力。

## 2. 状态与验收定义

- `NOT_TESTED`：未真正执行；`BLOCKED`：有客观阻断；`FAIL`：执行过但不符合目标；`PASS_MOCK`：仅模拟；`PASS_REAL`：与所需真实客户端、账户和上游核对过。
- **正式交付**：MG-R001..MG-R012 每项必须具有对应的 `PASS_REAL` 证据（纯安全/静态不变量允许额外静态检查，但不能替代真实场景）。全数通过后仍需所有者批准发布。
- 任何测试使用不同父 GPT 模型、跳过关键场景、替代 GUI 为 CLI、MCP 假装原生、静默隐藏模型，均不得签收。
- **Codex 测试限制**：所有通过原版 Codex 发出的真实 GPT 推理只能使用 GPT-6 Luna；这不禁止对 OpenCode DeepSeek/其他非 GPT 子模型进行目标验收；不允许自动 fallback 到其他 GPT。普通零出站 mock 无真实模型费用，也不能当真实 Luna 验收。
- 显式 `BLOCKED` 不是降级；保留所有目标并提供根因、替代实现的研究证据及恢复条件，不得宣称已完成。

## 3. 变更申请与权限模型

- 仅所有者可以批准修改需求 ID、验收指标、原生能力定义、模型覆盖范围、默认体验或 GPT-6 Luna 测试限制。
- AI 可以在独立 PR 中提出变更建议，但不能在没有所有者明确书面批准时修改受保护契约和外部验收预期，不能通过修改用词或删除测试隐式降级。
- 原始要求与已签收变更应通过所有者控制的受保护分支 / 外部只读快照保存；本仓库中的 guard 只是辅助手段，**单独仓库内脚本不构成真正防篡改**。
- 主线及正式集成分支必须启用 PR、必需检查、CODEOWNERS、禁止强推、禁止绕过；开发 Agent 所用 GitHub 身份不得具备更改 Ruleset/契约仓库的权限。这一步需要拥有相关管理权限的所有者执行并核实，不能靠文本宣称已开启。
- 生产部署、真实付费联调、超预算测试、安装依赖/下载大型资源、合并/发布均须符合已有 [资源授权](../../RESOURCE_APPROVAL.md) 与明确用户授权；不得因为授权受限改动目标。

## 4. 独立验收（防止开发者改测试自行过关）

- 开发者与验收者职责分离；验收从本契约出发，而不是从作者提交的“已完成”声明出发。
- 外部验收仓库或所有者管理的 CI 保存不可由开发 Agent 修改的关键端到端测试和期望 SHA；项目内 `scripts/check-product-contract.mjs` 只保证文件存在/形式和最基本字段。
- 每次结论必须绑定唯一源码 commit SHA、环境版本与每条用例的原始脱敏证据；代码或测试变化后，旧证据不能复用。
- 需要用户交互或收费的测试必须申请授权；未授权按 `BLOCKED`/ `NOT_TESTED`，不能默认调用其它模型。
