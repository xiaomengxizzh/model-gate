## 0. 产品使命、真实成功条件与非目标

### 0.1 使命

将 ModelGate 构建为可长期维护的多供应商模型管理与 Codex 适配层：在受支持的前提下让 Codex CLI / Desktop 的**同一新会话**可选择官方 GPT 和第三方 OpenCode Go DeepSeek 等模型，并支持 GPT 主代理向第三方子代理分派真实任务；同时维护动态模型目录、智能容错、配置所有权、选择性历史迁移与官方额度应急能力。

当前已有 ModelGate Gateway Core、Responses/Chat 桥、SSE、429 治理、Provider/模型管理与 /ui-next。**复用这些能力，不并行重建另一个通用网关，也不重做整套前端。**

### 0.2 三级成功里程碑

- **M1 聚合基础可用**：经过授权的真实 Codex CLI 与 Desktop，模型选择器同时显示官方 GPT 与第三方模型；在**同一个会话**完成 GPT → DeepSeek → GPT，后续轮次、工具状态和历史恢复真实有效。
- **M2 异构子代理可用**：保留新版 v2 优先设计；GPT 主代理创建第三方子代理，第三方收到**可读且完整**的任务、完成允许的真实工具调用、回传结果，主代理继续执行；失败必须显式显示。
- **M3 产品化**：具有可验证的智能跨模型恢复、费用保护、目录发布、生效诊断、受控配置更新、选择性历史处理、额度应急、安全审计与回滚能力。

**不得把模型出现在列表、Mock 成功、一次文本生成或一条 200 SSE 响应当作 M1/M2/M3 完成。**

### 0.3 非目标

- 不把 ChatGPT 个人订阅转为 DSH/UHR/任意 SDK 可调用的共享 API；不转卖/共享账号、规避官方限制。
- 不制作或下载开源模型权重、模型训练环境、深度学习框架；不重构 UHR Harness。
- 不尝试未经授权解密、伪造或删改 Codex v2 密文来制造“恢复成功”。
- 不以重写旧 Codex 历史数据库作为聚合模式首要实现路径。
- 不默认任何现有或未来 Codex 版本均支持内置 openai 身份接管。

## 1. D1–D7：已锁定的所有者决策

| 决策 | 选择 | 正式实施契约 | 不允许的行为 |
|---|---|---|---|
| **D1 聚合身份** | **A：沿用 Codex 内置 openai Provider 身份** | 研究并采用 CC Switch 条件式统一身份路线；保留官方登录，按用户选模型由网关选择官方或第三方；版本/账号/客户端能力必须真实验证 | 不能把保留 openai 名称当作已证明兼容或合规；官方凭据不能发送第三方 |
| **D2 模型目录** | **B：动态维护本地 Codex JSON** | 官方可信来源 + 已配置第三方 → 完整 Codex 元数据 → 校验与去重 → 版本化本地 JSON → 检测差异 → 受控发布 | 不能将普通 OpenAI /v1/models 返回直接当完整 Codex catalog；不得未经确认重启运行客户端 |
| **D3 子代理** | **C：v2 优先、研究加密任务恢复** | 保留原生 v2 的新式协作能力，分析密文结构、可读任务重建、安全恢复及兼容性，无法验证时显式阻断 | 不默认全局切回 v1，不允许猜测密文、删除密文、隐藏不兼容错误 |
| **D4 Fallback** | **C：智能跨模型** | 只在已授权候选里按错误类别、功能、可读性、上下文、费用及工具副作用判断，必要时自动恢复 | 不调用未授权收费服务，不把官方订阅当通用备用池，不盲目重放工具/流 |
| **D5 配置** | **B：受控自动管理** | 声明所有权的字段才可改，展示 diff，用户确认，原子写入、版本检查、并发冲突、备份/回滚 | 不整文件覆盖 config.toml、不触碰 auth.json、不私改 MCP/权限、不强制杀进程 |
| **D6 历史** | **B：默认只读、按需迁移** | 首先扫描与诊断；单条会话迁移需另行授权、备份、模拟和回滚演练 | 不批量改写，不把 Provider 元数据更正当作 v2 密文恢复 |
| **D7 额度** | **B：预警 + 手动应急模式** | 信任额度来源，阈值提醒；额度耗尽时明确展示影响，在独立确认后可进入第三方应急态，并可恢复 | 不自动绕过额度、购买 API 额度、退出/删除官方登录或偷偷改变会话分组 |

## 2. 各决策之间的依赖和不可混淆之处

1. **D1 × D2：内置 openai 不等于任意远程目录。** Codex 限制内置 openai 的 model_catalog_url 所能使用的主机。第一步应使用启动时加载的本地 model_catalog_json；必须生成真正的 Codex 完整目录，不能直接使用简单 OpenAI /v1/models 格式。
2. **D1 × D3：相同 Provider 身份不保证 v2 子代理任务可读。** 原生后端形成的加密 agent_message 可能在第三方线路重放，导致后续请求持续失败；密文不是路由器可以直接修复的内容。
3. **D3 × D4：智能选择模型必须在任务可读性检查之后。** 备用模型再多，若无能力读取任务或者无法维持工具契约，也不能对密文任务自动换上游。
4. **D4 × D7：官方订阅不进入通用 Fallback 池。** 正常官方 Codex 使用、第三方 API 计费和 ModelGate 管理端身份分开；不能借由路由把个人套餐变成跨客户端 API。
5. **D2 × D5：自动发现 ≠ 自动应用。** 可自动生成候选目录，但正式文件写入、冲突覆盖及客户端重启依 D5 的预览与授权流程执行。
6. **D5 × D6：配置写入权 ≠ 历史修改权。** 更新 config.toml 绝不可同时触发 sessions / state DB 的迁移。
7. **D1 × D7：正常态 openai，应急可能使用 custom。** 额度限制后 Codex 可能在客户端直接锁定发送按钮，ModelGate HTTP 层无法独自解决。第三方应急模式可能改变会话归属/可见性，必须提示并支持退出、不得宣称无缝。
8. **D4 × 工具副作用：429 或 5xx 不是安全重放的充分条件。** 请求可能已经执行部分 shell、MCP 或文件写入；“没收到结果”不能等同“没执行”。

## 3. 合规、凭据、权限及费用硬约束

### 3.1 身份隔离

必须建三个完全不同的身份域：客户端对 ModelGate 的认证、ChatGPT/Codex 官方登录、第三方模型上游凭据。官方相关令牌和 ChatGPT-Account-ID 等标识**只在受支持且经过核实的官方请求路径中使用**，第三方请求清除所有官方专用头；第三方密钥不能进入官方路径。禁止开放可把官方订阅当作通用 API 的入口。

在实施官方登录透传之前，核查当期适用的 OpenAI 文档、账号使用条款与客户端版本。**如果官方支持/政策范围仍不明确，不执行真实官方订阅透传，保留官方直连。**

### 3.2 路由边界

- 聚合模型 ID 采用稳定、不可重绑定的专用命名方案，保留原供应商/原模型映射，不允许同名新模型偷换身份。
- 未找到或已移除的聚合模型立即返回带错误码的明确失败；不得回退 defaults.provider。
- 对官方目标实施 host/path 明确白名单、重定向禁用、SSRF 防护；来源不可信时 fail closed。
- 错误/遥测只记录模型、供应商、错误类别、时间、预算、是否回退等最小数据；不能记录令牌、原始密文、敏感输入/响应。

### 3.3 费用与可靠性

- 用户对每个候选供应商、模型和预算提供明确授权；未批准新增收费途径的 Fallback 直接拒绝。
- 费用预算：单请求/单任务/日累计上限，超限需停机而非悄悄降级；模型清单中的价格/能力是计划元数据，不能代替真实结算/能力验证。
- 必须区分短暂 429/Retry-After、供应商 5xx、余额 402、模型 404、参数 400/422、权限 401/403、流中断、客户端取消和不可读 v2 密文。
- 真实工具调用及 hosted tools 可能有副作用，不可仅因 API 重试条件满足就重放。已发送可见内容的 SSE 不能拼接另一个模型输出伪装无中断。

### 3.4 用户环境与依赖限制

未经用户另行明确批准，**不得下载或安装任何大容量程序、套件、框架、权重或训练依赖**。对于任何拟新增依赖，必须先检查本机是否已有，优先 Node.js/仓库现有环境、内置标准库、现有 API 或轻量 CLI。不要对真实正式环境、Git 主线、运行中服务实施未经批准的变更。

### 建议的逻辑模块边界（可根据现有目录微调）

- codex/catalog：来源、模型元数据、去重、稳定 ID、版本化目录、校验、缓存、生效状态。
- codex/identity：正常态内置 openai 条件、身份一致性判断与应急状态机。
- codex/auth：官方目标与第三方上游的凭据路由、Headers 白名单、审计与脱敏。
- codex/interop：Responses/Chat 工具函数、namespace 展开与还原、replay 与 unsupported 错误。
- codex/agents：v2 任务可读性和加密边界判定、可授权明文重新委派研究。
- routing/decision：在既有 forwardChain 内增加模型候选评分、预算、错误分类、工具副作用保护。
- codex/config：字段所有权、差异、版本检测、备份、原子写入、恢复。
- codex/history：只读诊断；后续经批准才实现写入型迁移。
- codex/quota：可信额度来源、阈值、应急模式、恢复记录。
- ui-next：扩展现有页面，建设聚合模型、客户端状态和诊断区；不整站重做。

## 5. 执行阶段 E0–E9

### E0｜环境与证据基线（所有后续工作的前置）

- 阅读当前仓库 README、配置、docs/roadmap、Draft PR #5/#4/#2 和历史验收文档。
- 确认最新 commit SHA、现有 Codex CLI/Desktop 版本、现有 Node/工具及权限约束。
- 使用临时 CODEX_HOME、隔离实例、Mock 上游和独立测试目录，确认不触碰正式 auth、sessions、config.toml、8787/systemd。
- **验收：** 明确 CODEX_HOME、工作树、端口、测试数据及回滚的隔离边界，旧应用仍保持原状。

### E1｜P0：官方身份与第三方凭据隔离

- 实施目标路径白名单、官方头/第三方头过滤、请求身份分类、明确授权的官方透传及密钥保护。
- 未知聚合 ID 不允许默认上游 Fallback；把原始模型、真实模型、Provider 和路由原因纳入脱敏审计。
- **验收：** 使用 Mock echo upstream 检查每个敏感 Header 的允许/禁止集合，测试错配 host、重定向、恶意 extraHeaders、跨来源回退，确保零串线。

### E2｜P0：动态本地聚合目录

- 构建 Codex 模型目录生成器：从可信且允许的官方来源/现有缓存和 ModelGate 已配置第三方生成完整 Codex 元数据。
- 稳定模型 ID，不复用历史 ID 指向新供应商；上下文、推理等级、模态、工具支持要有来源与置信度。
- 自动检测差异并生成新版本，旧目录回滚可用；标记“已生成/已发布/客户端可能陈旧/已真实识别”。
- **验收：** 模型目录通过目标 Codex 解析，经过实际重新加载后同时出现官方与第三方；未授权修改正式 Codex 配置前只在隔离环境验证。

### E3｜P0：D1-A 同会话模型切换

- 在隔离 Codex CLI 验证内置 openai 的条件式入口、官方身份路由、第三方切换、连续轮次与 SSE；通过后再经授权测 Desktop。
- 不修改现有历史或官方认证文件；真实官方登录测试的账号/政策/费用授权单独确认。
- **验收：** 同一线程 GPT → DeepSeek → GPT，工具环境与历史模型身份正确，resume 不出现 Provider mismatch；CLI、Desktop 分别报告。

### E4｜P0：v2 跨供应商子代理

- 确认当前 Codex v2 任务格式、加密内容和 replay 行为，探索**受支持且获得授权**的明文任务重建/委派途径。
- 对无法理解的加密 agent_message 明确错误，不删除/伪造密文；不得偷偷切换整会话为 v1。
- 解决第三方 Responses/Chat 工具声明、namespace 工具函数往返、call_id 配对、结果回传与主代理续轮。
- **验收：** GPT 主代理真创建第三方子代理，收到完整可读任务并执行允许的真实工具，父代理使用其结果继续；达不到则明确 BLOCKED 并提交证据，不能换名宣布完成。

### E5｜P0：智能跨模型 Fallback

- 构建明确授权候选池；筛选 task_readability、API、工具、上下文、模态、预计费用与健康状态。
- 请求状态机区分：未发送、上游受理但无可证副作用、已出现工具或 hosted side-effect、已交付有效流、任务部分提交、用户取消。
- 只在证明安全且未越预算的情况下自动重试/换模型；其他情况返回可解释错误，并允许用户主动发起新任务而非隐式重放。
- **验收：** 注入 429/5xx/timeout/402/错误参数、断流、取消、未知密文/工具副作用；证明不会出现未授权费用和重复外部操作。

### E6｜P1：受控 Codex 配置应用与 UI

- 在 ui-next 中显示变更前后差异、字段所有者、目录世代、加载状态、冲突提示。
- 对受支持的本地文件执行原子备份/写入/回滚；写入前重新校验文件哈希与用户授权；不具备本地写权限时仅允许导出/显示说明。
- 不重启运行中 Codex；发现 CC Switch/其他程序控制同字段时中止。
- **验收：** 配置变更后原有 MCP、权限、自定义未知字段保持；并发外部修改被拦截；失败可恢复。

### E7｜P1：历史只读分析与可选迁移

- 默认只读识别 provider 组、目录缺失、工具回放、v2 加密历史和可恢复性。
- 先使用人工合成会话和隔离数据库研究选择性迁移账本、备份与恢复；不得实际迁移用户会话，除非再次逐条授权。
- **验收：** 只改授权对象，未选历史与原始副本不变；故障能完整恢复；真实迁移标 NOT_RUN 直到授权。

### E8｜P1：官方额度预警与手动应急

- 读取可信且允许的官方额度数据；不存在数据时展示 UNKNOWN 而不是虚构余额。
- 展示预警阈值、官方额度锁定的客户端层限制、应急模式影响与备份点。
- 用户单独确认且无正在运行的任务时，才准备由 openai 正常态进入第三方应急态；可能改变 Provider 分组、会话可见性和启动要求；明确提供回退流程。
- **验收：** 没有未授权身份/账单变化；可以清楚解释应急状态、新会话归属和旧会话可见性。

### E9｜集成、合并评审与发布闸门

- 验证从代码到 UI 的完整路径；真实账号调用、真实收费与 Desktop 测试另行获得明确授权。
- 单独提供 Mock、STATIC、CLI LIVE、Desktop LIVE、TOOLS LIVE、NOT_RUN 的矩阵；不得以历史记录替代最新 exact-head 运行。
- 每个阶段留下版本、commit SHA、脱敏配置哈希、操作、预期/实际、关键错误、回滚与费用记录。
- **验收：** P0 全通过、权限合规检查通过、现有自动化测试不回退、Draft PR 有审计证据。仅向所有者提交合并建议，不能擅自合并或部署。

### 阶段依赖

**关键主链：E0 → E1 → E2 → E3 → E4 → E5 → E9。**

E6 可于 E1/E2 通过后并行，但只能在隔离环境预览；E7 在 E3 后做只读诊断；E8 在 E3 后做额度逻辑，正式应急测试需另行授权。
