## 立即行动

A. **先审计，不要直接改现有文件。** 罗列旧前端每一个真实功能、URL、后端返回字段和失败路径，整理功能迁移矩阵：保留、重设计、明确废弃、后台未支持。除了 provider/model/virtual model 之外，必须覆盖默认目录、fallback、代理、QPS、配额、Key、route preview、configVersion=409、探活、模型测试、日志、统计、主题和管理认证。找出曾经因保存导致配置字段被清掉的潜在风险。

B. **全新产品设计。** 设计 6 个一级页面：总览、供应商、模型与路由、客户端连接、监控与诊断、安全与设置。产出用户流程、信息架构、线框描述、设计 token、组件规格、不同状态、数据密度方案和移动断点。视觉采用专业技术控制台风格，不沿用原赛璐璐界面。必须提供亮/暗主题、无障碍、响应式和空/加载/错误/无权限状态。不得用静态漂亮假图冒充工作控制台。

C. **纯代码从零构建。** 首选 HTML/CSS/ES modules，建立 src/ui-next/ 下的新工程文件，不引入 React/Vite/大前端依赖作为隐性前置。分离 API client、token 管理、state、组件、视图、表单校验、统计图。先把新 UI 发布到隔离开发入口（如 /ui-next），保留旧 / 和 /admin 面板在验收期运行。现有 Node 静态服务可在后端确认后以最小受控改动支持该路径；不得独自改动网关核心路由、权限和模型协议。

D. **与后端合同联动，不等后端全部做完。** 从 F0 功能矩阵和 F1 骨架起步，使用准确且标注 MOCK 的 fixture；后端冻结 /api/* schema 后做 F2 Provider/Model/VirtualModel CRUD、Key、安全保存、409 冲突差异、路由预览与模型测试的真实联动；F3 实现监控、错误追踪和 Codex/DSH 接入向导。后端尚未支持的 trace/Clients 元数据必须标“尚未提供”，禁止造成功能已上线的假象。

E. **安全与可靠性自测。** 管理 token/API Key 不明文写 localStorage、URL、日志或 Git；日志和用户可输入字段使用安全 DOM 文本，不做无审查的 innerHTML 注入。测试 390/768/1024/1440 的布局、键盘焦点/关闭弹窗、保存失败、409 并发、401、网络中断、429、空数据、长列表、双主题和移动端。自动化检查只能用宿主已有浏览器/工具；若没有便标 NOT_RUN_BROWSER，不能安装新浏览器包或依赖。

F. 每阶段提交到你**独立**的 dev/frontend-<任务>-<日期> 分支，以独立 PR 提供截图/录屏（无私密内容）、功能迁移矩阵、接口测试、可用性与回归证据。网关后端 AI 有自己的分支和工作目录，不能跟他同时修改同一分支、共享工作树或生产 config。提前约定 API 契约，发生远端变动核对最新 SHA 后处理。

## 成败门禁

- **成功**：旧前端所有有价值的实际业务能力在新 UI 可用并可证明；新设计具有明显的独立信息架构、组件系统和新交互；页面直接调真实 API，状态与错误真实；不会丢配置、Key、stats，旧数据不用迁移或损坏；用户批准切换后才能退役旧界面。
- **失败**：只交付静态 Dashboard、只换肤/改配色、复制旧 admin.html 拆成几份、删除旧 UI 导致生产失效、没有敏感配置防护、没有保存冲突处理、在没有实际支持时宣称 Codex/DeepSeek 已经连通。
- **发布**：F0→F1→F2→F3→F4→F5；全部在隔离实例和模拟环境完成。只有在我另行批准上线、具备明确回滚和全面验收后，才能替换旧 /admin/ 根入口并删除旧页面运行文件。历史 Git 可回滚。

## 资源与安全限制（最高优先级）

**新增大型安装/下载：无；历史提议仅供研究，不自动执行。** 任何依赖（包括小依赖）安装/下载/升级前必须先盘点真实宿主现有程序版本、跨项目缓存/共享副本和重复下载风险；无法检查写 UNKNOWN_LOCAL_STATE。即便查明确实缺失也不代表允许安装。禁止未获用户明确授权就加入大型前端 UI 包、训练套件、模型权重、容器镜像、Playwright/Chromium 下载；禁止通过 npm install、npx、CI、子代理绕过。优先原生 HTML/CSS/JS，用户已有浏览器和 Node。禁止上传/泄漏任何凭据、真实日志正文和用户敏感数据。
